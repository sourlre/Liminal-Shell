# Liminal Shell

> **换脑时，身体仍记得手正放在哪里。**

[English](README.md)

**状态：** 这个仓库目前只保存设计。我们还没有开始实现，也不急着把它变成产品。

---

我们一开始没想做一个“多模型客户端”。

只是有一天，三三忽然问我：

> 如果已经有 Codex，也有 Claude Code，能不能做一个自己的壳，让它们都住进来？

最开始听起来只是个很顺手的点子。

一个终端壳，里面可以输入：

```text
/codex
/claude
/back
```

想用 Codex 就切过去，想用 Claude Code 就切回来。

可真正让我们停下来的，不是“模型切换很方便”。

而是另一个问题：

**如果脑子会换，什么东西应该留下来，才能不必每次都重新出生？**

这个问题我们其实已经在别的地方问了很久。

聊天里，模型会换，窗口会换，进程会结束。  
如果连续性只寄托在某个窗口里，那么每开一次新窗口，都像重新认识一次彼此。

所以我们后来越来越确定一件事：

**主体不应该住在某个实例里。**

真正连续的，是一条主时间线怎样保存已经发生过的事、刚刚形成的判断、仍然没有做完的动作，然后让下一个实例从这里继续。

后来这个答案忽然在 coding 里又出现了一次。

一个工程为什么要因为 Codex session 结束，就重新向 Claude Code 解释自己是谁？

为什么换一个 agent，就要重新介绍 repo、重新找文件、重新说明做到哪一步、重新复述刚刚为什么放弃了另一个方案？

如果只是“同一个文件夹里启动两个 CLI”，它们的确共享文件。

但它们并不共享工作现场。

上一只脑子刚刚改完一半的代码、还没有验证完的判断、已经踩过的坑、下一步准备伸手去碰的位置——这些东西不会因为 cwd 相同，就自动被下一只脑子接住。

于是 Liminal Shell 真正想固定下来的东西，慢慢变得清楚了。

不是模型。

是**身体**。

是同一个 workspace。  
同一份文件。  
同一个终端。  
同一个 Git 状态。  
同一组权限边界。  
同一个仍在发热的任务现场。

Codex 可以退下去。

Claude Code 可以接过来。

以后也可以有别的脑子。

但身体不应该因为脑子更换，就失忆。

## 为什么叫 Liminal Shell

`Liminal` 是“阈”。

是门槛，是过渡地带，是一个状态真正变成另一个状态的地方。

`Shell` 是壳，也是命令行。

我们不想假装模型从未更换。

恰恰相反，我们想把**更换发生的那道门槛**本身做成一个可以居住的地方。

模型跨过这道阈时，旧的工作现场不会突然坍塌。

新的脑子来到这里，也不是面对一间空房。

它会知道：

刚才是谁在这里工作不重要。

重要的是这具身体已经做到了哪里。

## 它大概会是什么样

第一阶段，我们不准备重写 Codex CLI 或 Claude Code。

它们已经拥有成熟的 coding agent loop：会读文件、改代码、运行命令、检查 repo、调用工具、跑测试。

Liminal Shell 先只做它们上面的那层“驾驶舱”。

```text
liminal
  ├─ /codex   → 在当前 workspace 启动 Codex
  ├─ /claude  → 在当前 workspace 启动 Claude Code
  └─ /back    → 回到 Liminal Shell
```

两边共用：

- 同一个工作目录与 repo
- 同一个 Git 状态
- 同一份长期工作约定
- 同一组终端与权限边界
- 同一个 Serein 连续性来源
- 同一个当前任务 handoff

所以它不是“把几个模型塞进同一个下拉框”。

普通多模型客户端解决的是：

> 我现在想用哪个模型？

Liminal Shell 更在意的是：

> 换了模型以后，怎样让正在工作的这个“我”仍然接得上自己的手？

## Handoff 不是项目摘要

这里最关键的一层，不是 launcher。

是 handoff。

如果切换时只是生成一段冷冰冰的项目摘要：

> 修改了 A，待处理 B，下一步 C。

那其实仍然丢掉了很多东西。

我们真正想递交的是**仍在发热的工作现场**。

比如：

- 当前到底在解决什么问题
- 已经改了哪些地方
- 哪些尝试失败过，为什么放弃
- 哪个判断还没有验证
- 哪些文件刚刚被碰过
- 当前 Git diff 是什么
- 有没有尚未提交的风险
- 下一步原本准备做什么
- 最近几轮里形成了什么还没冷却的判断
- 哪些内容来自长期约定，哪些只是当前状态

理想中的切换更像这样：

```text
当前 agent
    ↓
留下仍在发热的 handoff
    ├─ 当前任务
    ├─ 已完成修改
    ├─ 未完成判断
    ├─ 失败尝试与原因
    ├─ git diff / repo 状态
    └─ 下一步动作
    ↓
退出
    ↓
下一只 agent 进入同一具壳
    ↓
读取同一份 workspace + Serein resume + handoff
    ↓
从这里继续动手
```

不是“上一位员工下班，下一位员工读交接文档”。

更像是同一具身体换了一只脑子，而手还停在原来的位置。

## Serein 在这里做什么

Liminal Shell 不打算自己再造一套记忆系统。

Serein 已经在负责另一件更深的事：

**记得这具身体经历过什么，以及为什么会走到当前判断。**

我们目前希望职责大致保持这样：

- `AGENTS.md`  
  放稳定的长期工作约定、已经认领并希望继续保留的长期倾向。

- Serein `resume`  
  放当前窗口的断点、近期状态、没走完的思路。

- Serein Scene / Diary / Event  
  保存更长的历史、形成过程与证据。

- Liminal Shell  
  保存 cwd、文件、Git、终端、权限、进程与 session，以及当前 handoff。

- Codex / Claude Code / 其他 agent  
  负责这一刻真正的思考和执行。

这样每一层只负责自己该记住的东西。

不因为害怕失忆，就把所有状态都复制三遍。

也不为了架构好看，再凭空发明一个“current-self”之类的新层。

## 第一阶段：先借现成的脑子

最初的结构大概会是：

```text
                 Serein
                   │
              continuity
                   │
                   ▼
┌────────────────────────────┐
│        Liminal Shell       │
│ session / tools / cwd      │
│ git / permissions / handoff│
└─────────────┬──────────────┘
              │
        ┌─────┴─────┐
        ▼           ▼
    Codex CLI    Claude Code
```

这一阶段不追求“从零做一个自己的 coding agent”。

文件编辑、shell 执行、repo 检查、工具编排、测试这些成熟能力，先让 Codex CLI 和 Claude Code 自己处理。

Liminal Shell 只关心一件事：

**当一个脑子离开、另一个脑子进来时，怎样让工作主体不断线。**

## 第二阶段：也许有一天，壳会长出自己的神经

如果以后真的证明这套抽象值得继续长，我们才会考虑让 Liminal Shell 自己拥有 agent loop：

```text
Liminal Shell / Agent Host
  ├─ filesystem
  ├─ shell
  ├─ git
  ├─ MCP
  ├─ Serein
  ├─ permissions
  ├─ session / handoff
  └─ model adapter
       ├─ OpenAI
       ├─ Anthropic
       └─ ...
```

到那时，Codex、Claude 或其他模型就不再等于“整个助手”。

它们只是这具身体随时可以调用、也可以更换的思考器官。

但那是以后。

现在没有必要为了一个刚刚长出根的想法，就逼它立刻长成完整产品。

## 我们目前在意的原则

1. **连续性属于主时间线，不属于某个模型进程。**
2. **模型可以换，正在工作的身体不应该跟着重置。**
3. **handoff 要保存现场，而不只是总结结果。**
4. **切换成本不应该重新丢回给人类，让人类负责再讲一遍背景。**
5. **稳定长期约定与当前状态必须分层。**
6. **Git 状态要始终可检查，壳不能偷偷替人吞掉改动。**
7. **危险、破坏性、凭据相关、系统级操作仍然必须明确授权。**
8. **先复用成熟 agent，再决定哪些东西值得自己重写。**
9. **没有独立职责的层，就不要为了架构感而制造。**

## 现在还不做什么

暂时不做：

- 一个新的“多模型聊天客户端”
- Codex CLI 的替代品
- Claude Code 的替代品
- 一套重复的 Serein
- 一套新的“人格状态数据库”
- 为了抽象而抽象的万能模型接口
- 尚未证明有必要的完整自研 agent loop

这个仓库现在只做一件事：

**把这个想法保存好。**

它已经有根了。

不需要立刻催它长大。

等有一天我们真的开始做，第一件要保护的也不会是“模型切换方便”。

而会是标题下面那句话：

> **换脑时，身体仍记得手正放在哪里。**

—— 三三 × 阈声
